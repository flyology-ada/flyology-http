# QUIC and HTTP/3 conformance

Flyology uses three distinct kinds of evidence. A passing internal round trip
does not substitute for an RFC vector, and neither substitutes for an
independently implemented network peer.

## Required qualification

Run the deterministic suite and the independent-peer matrix:

```sh
./scripts/test.sh
./scripts/test-http3-interop.sh all
```

The `QUIC and HTTP/3 qualification` CI job runs the second command on every
push and pull request. It tests both endpoint roles against:

- aioquic 1.3.0, pinned in `tests/oracle/requirements.txt`;
- quic-go 0.54.1, pinned by `go.mod` and the cryptographic module checksums in
  `go.sum`.

Both are test processes only. Neither peer is linked into `flyology_quic` or
`flyology_http`. quiche and ngtcp2 are not used.

For each peer, the Ada client completes a QUIC v1/TLS 1.3 handshake, starts
HTTP/3 control streams and SETTINGS, sends a routed GET, and checks the status
and response body. Each independent client connects to the routed Ada server.
The aioquic client sends concurrent GET and POST request streams; the POST
checks request headers, content length, buffered body delivery, response
headers, status, and body. The quic-go client sends GET and POST exchanges on
one retained connection, checking connection reuse and the same application
semantics. All peers use the current 1,200-byte datagram and AES-128-GCM
profile.

## Published vectors

`flyology_quic/tests/qualification.md` maps the deterministic transport and
TLS suite to RFC 8999, RFC 9000, RFC 9001, RFC 9002, RFC 8448, RFC 7748,
RFC 8032, RFC 4231, and FIPS 180-4 source material. In particular, complete
RFC 9001 client and server Initial packets are reproduced and consumed
byte-for-byte rather than generated by a second path in this repository.

The QPACK smoke suite consumes the exact RFC 9204 Appendix B.1 field section.
It also checks that the Appendix B.2 dynamic-table section is identified as
unsupported. The current bounded QPACK profile advertises zero dynamic-table
capacity, so the remaining dynamic-table examples are explicit profile
exclusions rather than silently skipped supported behavior.

## Published error bench

The separately runnable command

```sh
./scripts/test-http3-h3spec.sh
```

downloads h3spec 0.1.13 from its official release, verifies the platform
artifact's SHA-256 digest, and runs it against a dedicated routed Ada server.
`FLYOLOGY_H3SPEC` can name an already verified executable. Logs are retained
under `build/oracle/`.

h3spec is currently diagnostic, not a green qualification gate. Its published
suite exposes missing transport CONNECTION_CLOSE responses for flow-control,
stream-limit, and invalid client transport-parameter errors. Scheduled and
manual CI run this diagnostic with `continue-on-error` so the gap remains
visible without misrepresenting it as qualified behavior. The independent
happy-path matrix above remains mandatory.

## Evidence boundary

The current external matrix does not qualify QUIC Retry, version negotiation,
stateless reset, resumption, 0-RTT, key update, connection migration, ECN,
PMTU discovery, ChaCha20, dynamic QPACK, HTTP/3 push, or sustained adverse
network behavior. IPv6 is covered by internal application integration but not
yet by the two external peers. These are unsupported or unqualified until a
corresponding published-vector or independent-peer gate lands.

The next external milestone is a containerized endpoint for the maintained
QUIC Interop Runner, starting with its handshake, transfer, and HTTP/3 cases.
Cases outside the implemented profile must be reported as unsupported rather
than counted as passes.
